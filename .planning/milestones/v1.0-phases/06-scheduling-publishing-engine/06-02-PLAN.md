       - Constructor: SchedulingRepository, post state machine import
       - `schedulePost(postId: string, scheduledAt: Date, timezone?: string, windowHours: number = 4)`:
         - Load post with variants via repository
         - Assert post status is APPROVED (or SCHEDULED for reschedule) using assertTransition or direct check
         - If timezone provided, convert scheduledAt from company timezone to UTC using dayjs with timezone plugin. If not provided, lookup Company.timezone from DB.
         - Calculate publishWindowExpiresAt = scheduledAt + windowHours
         - Update all APPROVED variants to SCHEDULED with scheduledAt and publishWindowExpiresAt
         - Update parent ContentPost to SCHEDULED with scheduledAt
         - Return updated post

       - `autoSlot(postId: string, timezone?: string)`:
         - Load post, get company timezone
         - Get company preferred posting windows (default: 9:00, 12:00, 17:00 in company TZ)
         - Find next available window (>= now + 1 hour minimum lead time)
         - Check if that window already has a post scheduled (avoid double-booking)
         - If occupied, try next window; if all today occupied, try tomorrow
         - Call schedulePost with the resolved time

       - `cancelSchedule(postId: string)`:
         - Load post, assert it's SCHEDULED
         - Update all SCHEDULED variants back to APPROVED, clear scheduledAt/publishWindowExpiresAt
         - Update ContentPost back to APPROVED, clear scheduledAt
