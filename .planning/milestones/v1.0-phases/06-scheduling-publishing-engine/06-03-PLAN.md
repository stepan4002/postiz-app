Implement the PlatformAdapter layer with 4 MVP platform adapters (Instagram, Facebook, LinkedIn, X) and an adapter registry for runtime lookup.

Purpose: Provides uniform publishing interface across all social platforms. Each adapter handles platform-specific API calls, payload formatting, and error classification. The registry enables the publishing worker to resolve the correct adapter by platform name.

Output: 4 platform adapter implementations, base adapter class, adapter registry, all with tests.

         - 429 / rate limit indicators -> { retryable: true, errorType: 'rate_limit' }
         - 5xx / timeout / ECONNRESET -> { retryable: true, errorType: 'transient' }
         - 4xx (except 429) / auth errors / policy violations -> { retryable: false, errorType: 'permanent' }

    2. Create `instagram.adapter.ts` extending BaseAdapter:
       - `platform = 'instagram'`
       - `apiVersion = 'v21.0'` (NF4.5 — pinned)
       - `publish(params: PublishParams)`:
         - If no mediaBuffer and no mediaUrl, return permanent error (Instagram requires media)
         - Step 1: Create media container via POST `https://graph.facebook.com/${apiVersion}/${igUserId}/media` with { image_url, caption }. The igUserId comes from the variant's linked SocialAccount (passed via params or resolved from integration). For our adapter, we pass igUserId as part of the accessToken flow — the adapter receives the page-scoped token and the IG user ID is the `id` field from the integration.
         - Actually, simplify: adapter receives `params.variant` which has the platform info, and `params.accessToken` which is the page-level access token. The adapter also needs the Instagram user ID — add an optional `platformAccountId` field to PublishParams for this.
         - Step 2: Poll container status until FINISHED (max 30s, poll every 2s)
         - Step 3: POST `https://graph.facebook.com/${apiVersion}/${igUserId}/media_publish` with { creation_id: containerId }
         - Return PublishResult with platformPostId and platformUrl
         - Wrap all fetch calls in try/catch, classify errors via base class

    3. Create `facebook.adapter.ts` extending BaseAdapter:
       - `platform = 'facebook'`
       - `apiVersion = 'v21.0'` (NF4.5 — pinned)
       - `publish(params: PublishParams)`:
         - Text-only: POST `https://graph.facebook.com/${apiVersion}/${pageId}/feed` with { message: caption }
         - With image: POST `https://graph.facebook.com/${apiVersion}/${pageId}/photos` with { url: mediaUrl, message: caption }
         - pageId from platformAccountId in PublishParams
         - Return PublishResult with platformPostId and platformUrl (https://facebook.com/{pageId}/posts/{postId})
         - Error classification via base class

    4. Update PublishParams in publishing.types.ts to include `platformAccountId?: string` — needed by adapters to know which page/account to publish to.
