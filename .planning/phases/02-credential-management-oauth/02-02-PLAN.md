    - refreshExpiringTokens() calls findTokensAt75Percent() and processes each result
    - On successful refresh: resetFailureCount called, token re-encrypted and saved
    - On failed refresh: incrementFailureCount called
    - On 3rd consecutive failure (consecutiveFailures reaches 3): NotificationService.inAppNotification() called with organizationId
    - Handles empty findTokensAt75Percent() result gracefully (no errors)
    - Decrypts tokens before passing to RefreshIntegrationService.refresh()
  </behavior>
  <action>
    1. Create src/refresh/token.refresh.job.ts:
       - @Injectable() TokenRefreshJob
       - Inject: CredentialRepository, TokenEncryptionService, NotificationService (from @gitroom/nestjs-libraries), PrismaService
       - @Cron(CronExpression.EVERY_10_MINUTES) refreshExpiringTokens():
         a. Guard: if (!process.env.RUN_CRON) return;
         b. const integrations = await this.credentialRepository.findTokensAt75Percent();
         c. For each integration:
            - Decrypt token and refreshToken using TokenEncryptionService (check tokenEncrypted flag first)
            - Attempt refresh using the upstream provider's refresh mechanism (call the social provider's refreshToken method via IntegrationService pattern)
            - On success: re-encrypt new tokens, save, resetFailureCount
            - On failure: incrementFailureCount, then check if consecutiveFailures >= 3 to trigger alert
       - maybeAlertOperator(integration): if consecutiveFailures >= 2 (about to become 3), call NotificationService.inAppNotification()
