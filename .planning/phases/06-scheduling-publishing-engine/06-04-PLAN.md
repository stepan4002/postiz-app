       - Constructor: AdapterRegistry, TokenEncryptionService, PublishAttemptLogger, PlatformMediaValidator, prisma (for SocialAccount/Integration lookup, media download)
       - `publishVariant(variant: any)`:
         - Lookup SocialAccount for variant.platform + brand (via variant.post.brandId)
         - Lookup Integration by SocialAccount.integrationId
         - Decrypt access token via TokenEncryptionService (if encrypted)
         - If variant.mediaVariantId: download media buffer from MinIO (S3 GetObjectCommand)

    3. Create `publishing-worker.job.ts` with @Injectable() class:
       - Constructor: SchedulingRepository (for findPublishingVariants query), PublishingService, PublishAttemptLogger, Logger, prisma
       - `@Cron('*/30 * * * * *')` — every 30 seconds (poll for PUBLISHING variants)
       - `processPublishingVariants()`:
         - Guard: `if (!process.env.RUN_CRON) return;`
         - Find variants with status=PUBLISHING (these were set by SchedulerTickJob)
         - For each variant (per-variant error isolation):
           - Check retry eligibility: if publishAttempts >= 3, mark FAILED
           - Check backoff: calculate next retry time = last attempt + backoff(attemptNumber). Backoff with jitter: base * 2^(attempt-1) + random(0, base*0.5). Base delays: 60s, 300s, 900s. If not yet due, skip.
           - Call publishingService.publishVariant(variant)
           - On success:
             - Update variant: status=PUBLISHED, platformPostId, platformUrl, publishedAt=now
             - Update parent ContentPost: if all variants terminal -> PUBLISHED (all success) or FAILED (any failed)
           - On retryable failure:
             - Increment publishAttempts and consecutiveFailures
             - Store lastPublishError
             - If publishAttempts >= 3: mark FAILED
             - Otherwise: variant stays PUBLISHING for next tick retry
           - On permanent failure:
             - Mark variant FAILED immediately
             - Store lastPublishError
           - Log attempt via PublishAttemptLogger in all cases
         - After processing all variants: check parent ContentPosts that have all variants in terminal state and update their status accordingly
