    ```
    model Brand {
      id          String     @id @default(uuid())
      companyId   String
      name        String
      slug        String
      logo        String?
      description String?
      createdAt   DateTime   @default(now())
      updatedAt   DateTime   @updatedAt
      company       Company      @relation(fields: [companyId], references: [id], onDelete: Cascade)
      brandVoice    BrandVoice?
      socialAccounts SocialAccount[]
      @@unique([companyId, slug])
    }
    ```

  <action>
    1. Install `nestjs-cls` in the company-context package:
    ```bash
    cd extensions/company-context && pnpm add nestjs-cls
    ```

    2. Create `extensions/company-context/src/prisma-company.factory.ts`:
    - Export `prismaWithCompany(prisma: PrismaService, companyId: string | null)` function
    - Use Prisma `$extends` to intercept `findMany`, `findFirst`, `findUnique`, `create`, `update`, `delete`, `count` on company-owned models
    - For read queries: inject `companyId` into `where` clause
    - For create: inject `companyId` into `data`
    - Maintain a `COMPANY_OWNED` Set listing models that should be filtered: `'Brand'`, `'BrandVoice'`, `'SocialAccount'`
    - Export `isCompanyOwned(model: string): boolean` helper
    - Handle null companyId gracefully (skip filtering if null — needed for admin/seed operations)

    3. Create `extensions/company-context/src/company-context.middleware.ts`:
    - Injectable NestJS middleware
    - Reads `companySlug` from request params (`:companySlug` route param) OR from `x-company-slug` header (for API clients)
    - Looks up Company by slug using PrismaService directly (not the scoped client — this is the bootstrap query)
    - If found: stores `companyId` and `companySlug` in CLS via `ClsService`
    - If not found: returns 404 with `{ error: "Company not found" }`
    - If no slug provided: continues without setting context (allows non-company routes to work)

    4. Create `extensions/company-context/src/company-context.module.ts`:
    - NestJS module that:
      a. Imports `ClsModule.forRoot({ global: true, middleware: { mount: true } })`
      b. Provides a `COMPANY_PRISMA` injection token that creates a company-scoped Prisma client using the factory + CLS companyId
      c. Exports the `COMPANY_PRISMA` provider for use in other modules
    - Register `CompanyContextMiddleware` for all routes via `configure(consumer)` in the module

    5. Update `extensions/company-context/src/index.ts` to barrel-export:
    - `CompanyContextModule`
    - `prismaWithCompany`
    - `isCompanyOwned`
    - `COMPANY_PRISMA` token

    6. Register `CompanyContextModule` in `apps/backend/src/app/app.module.ts`:
    - Add import: `import { CompanyContextModule } from '@social/company-context';`
    - Add to imports array
    - Add DIVERGENCE.md entry for app.module.ts modification

    IMPORTANT: NestJS services are singletons. Company context MUST use CLS (request-scoped) — never store in a singleton property. See Research anti-patterns.
    IMPORTANT: Verify `prisma.$extends` works with Postiz PrismaService. If it doesn't, fall back to a wrapper service with explicit where clauses. See Research open question #1.
